# Deploying KisanQ

One web service, one managed Postgres, one managed Redis — a modular monolith, not
microservices. `render.yaml` provisions all three as a Render Blueprint.

## First deploy

1. Push the repo to GitHub.
2. In Render: **New → Blueprint**, point it at the repo. It reads `render.yaml`.
3. Set the `sync: false` env vars in the dashboard:
   - `CORS_ORIGINS` — the deployed PWA origin(s), comma-separated. **Required**;
     an empty allow-list blocks all browsers.
   - `SMS_API_KEY`, `BHASHINI_API_KEY`, `DATA_GOV_API_KEY` — optional; leave blank
     to run on the stub SMS driver and seeded rates.
4. Deploy. `preDeployCommand` runs `db:migrate` against the new release before it
   serves traffic, so a migration never races a live version.
5. Seed a demo district once, from the Render shell: `npm run db:seed`.

## Going live with real SMS

`CHANNEL_DRIVER=stub` is the default and demos the entire product with no vendor
account. To send real DLT SMS:

1. Register the seven templates in `src/i18n/templates.ts` with your DLT provider
   and record the returned template ids.
2. Set `CHANNEL_DRIVER=msg91` and `SMS_API_KEY`.
3. Point the provider's inbound + delivery webhooks at:
   - `POST /api/v1/hooks/sms/inbound` (reply-by-digit)
   - `POST /api/v1/hooks/sms/dlr` (delivery receipts)
   - `POST /api/v1/hooks/ivr` (missed-call status)

DLT template registration is paperwork with a lead time, not an engineering task —
plan for it, don't block on it.

## Scheduled jobs

- **Daily rate ingest** — a Render Cron Job hitting `POST /api/v1/rates/ingest`
  (district/admin token), or a BullMQ repeatable job once a worker process is added.
- **Bank return-file import** — `POST /api/v1/hooks/bank/return-file` from the
  treasury integration or a nightly upload.

## What is hardened

- **CORS** is an explicit allow-list (`CORS_ORIGINS`), never `*`.
- **helmet** sets security headers; **body limit** is 1 MB.
- **Rate limits**: OTP request is 3/hour/mobile (row-backed, survives restarts) and
  10/hour/IP; other routes are globally capped.
- **Load shedding**: `@fastify/under-pressure` returns 503 with a retry hint rather
  than dying when the board and the app both stream — check `/api/v1/health/pressure`.
- **Secrets**: `JWT_SECRET` is generated by Render; OTPs, gate OTPs and refresh
  tokens are hashed at rest; `devCode` is only ever returned outside production.
- **Audit**: every token issue/serve, lot, payment transition, centre event and
  reschedule writes to `audit_log` with actor and before/after.
- **Idempotency**: every mutation (and every offline sync op) is deduped by key, so
  a double-tap or an outbox replay lands exactly once.

## Health

- `GET /api/v1/health` — liveness + level.
- `GET /api/v1/health/deep` — proves the DB connection.
- `GET /api/v1/health/pressure` — event-loop / heap pressure (from under-pressure).
